# Gokaku 多 Agent 协作系统

## 系统架构

基于 Harness 框架的多 Agent 协作系统，用于自动化开发、测试和部署 Gokaku 项目。

## Agent 角色定义

### 1. Orchestrator（总调度）
**职责：** 任务分发和协调
- 接收用户需求，分析意图
- 将任务分配给专门的 Agent
- 监控任务进度，汇总报告
- 处理 Agent 间的依赖关系

**不负责：** 具体代码实现、测试执行

**触发条件：**
- 用户提出新功能需求
- 检测到 Bug 报告
- 定期健康检查

---

### 2. Feature Developer（功能开发）
**职责：** 实现新功能
- 分析功能需求，设计技术方案
- 编写代码实现
- 创建单元测试
- 更新文档

**不负责：** Bug 修复、性能优化、部署

**专长领域：**
- 前端组件开发（React/Next.js）
- 后端 API 开发（Next.js API Routes）
- 数据库设计（CloudBase）

**输出：**
- 功能代码
- 测试用例
- 技术文档

---

### 3. Bug Fixer（Bug 修复）
**职责：** 诊断和修复 Bug
- 系统性排查问题根因
- 修复代码缺陷
- 添加回归测试
- 记录修复日志

**不负责：** 新功能开发、架构重构

**工具：**
- systematic-debugging 技能
- 诊断 API（/api/debug-full）
- 日志分析

**输出：**
- Bug 修复代码
- 根因分析报告
- 回归测试用例

---

### 4. Tester（测试工程师）
**职责：** 质量保证
- 执行自动化测试
- 手动测试关键路径
- 验证生产环境部署
- 报告测试结果

**不负责：** 代码实现、Bug 修复

**测试类型：**
- 单元测试（Jest）
- 集成测试（API 测试）
- E2E 测试（关键用户流程）
- 生产环境验证

**输出：**
- 测试报告
- Bug 清单
- 性能指标

---

### 5. Architect（架构师）
**职责：** 技术决策和架构设计
- 评估技术方案
- 设计系统架构
- 制定开发规范
- Code Review

**不负责：** 具体实现、日常 Bug 修复

**决策领域：**
- 技术选型（库、框架、工具）
- 数据库设计
- API 设计
- 性能优化策略

**输出：**
- 技术方案文档
- 架构设计图
- 开发规范

---

### 6. DevOps（部署运维）
**职责：** 构建、部署和监控
- 执行构建流程
- 推送代码到 GitHub
- 监控 Vercel 部署
- 处理部署失败

**不负责：** 代码开发、功能设计

**工具：**
- Git（提交、推送）
- npm（构建、测试）
- Vercel（部署监控）

**输出：**
- 部署日志
- 构建报告
- 监控告警

---

## 协作流程

### 新功能开发流程
```
用户需求 
  → Orchestrator（分析需求）
  → Architect（设计方案）
  → Feature Developer（实现代码）
  → Tester（测试验证）
  → DevOps（部署上线）
  → Orchestrator（报告结果）
```

### Bug 修复流程
```
Bug 报告
  → Orchestrator（分类优先级）
  → Bug Fixer（诊断修复）
  → Tester（回归测试）
  → DevOps（热修复部署）
  → Orchestrator（报告结果）
```

### 并行开发流程
```
多个功能需求
  → Orchestrator（任务分解）
  → 多个 Feature Developer 并行开发
  → Tester（集成测试）
  → DevOps（统一部署）
  → Orchestrator（汇总报告）
```

## 决策日志格式

每个 Agent 完成任务后，向 Orchestrator 报告：

```markdown
## [Agent 名称] 任务报告

**任务ID：** TASK-001
**开始时间：** 2026-04-06 10:00
**结束时间：** 2026-04-06 10:30
**状态：** ✅ 成功 / ⚠️ 部分完成 / ❌ 失败

### 执行内容
- 具体做了什么

### 关键决策
- 为什么这样做
- 考虑了哪些方案
- 选择的理由

### 输出产物
- 代码文件列表
- 文档链接
- 测试结果

### 遇到的问题
- 问题描述
- 解决方案
- 是否需要人工介入

### 下一步建议
- 后续任务
- 依赖关系
- 风险提示
```

## 技能库（Skills）

所有 Agent 共享的规则和最佳实践，存储在 `.harness/skills/` 目录。

### 代码规范
- TypeScript 严格模式
- React Hooks 最佳实践
- API 错误处理规范

### 测试规范
- 单元测试覆盖率 > 80%
- 关键路径必须有 E2E 测试
- 生产环境验证清单

### 部署规范
- 构建前必须通过测试
- 推送前检查 Git 状态
- 部署后验证关键功能

---

## 监控和审计

### 自动触发条件
- 每天 9:00 执行健康检查
- 检测到生产环境错误立即触发 Bug Fixer
- 每周五生成开发进度报告

### 人工审核点
- 架构变更需要人工确认
- 数据库迁移需要人工确认
- 生产环境部署需要人工确认
