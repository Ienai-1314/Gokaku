## 🔧 技术方案

### PDF 处理流程
```
PDF 扫描版
  ↓
MinerU API (OCR)
  ↓
Markdown 文本
  ↓
DeepSeek API (结构化)
  ↓
JSON 题目数据
  ↓
CloudBase 数据库
```

### 关键技术栈
- **OCR：** MinerU API (vlm 版本)
- **AI 解析：** DeepSeek API
- **数据库：** 腾讯云 CloudBase
- **前端：** Next.js 14 + React
- **后端：** Next.js API Routes
- **部署：** Vercel

## ⚠️ 发现的问题

### 1. DeepSeek 解析不稳定
- **现象：** API 调用超时或返回格式错误
- **原因：** 单次处理内容过大（2000+ 行 Markdown）
- **影响：** 无法批量解析新提取的 Markdown
- **建议解决方案：**
  * 分段处理（每次 500 行）
  * 增加重试机制
  * 优化 prompt 减少输出量

### 2. 历史数据不一致
- **现象：** 之前报告有 308 道题，实际只有 100 道
- **原因：** 可能是不同环境或测试数据
- **影响：** 无实际影响，当前数据完整
- **建议：** 统一使用生产环境数据

### 3. 大量资源待提取
- **现象：** 189 个 PDF 文件未提取（93%）
- **原因：** 时间限制和 API 调用成本
- **影响：** 题库规模较小
- **建议：** 优先提取语法资料（4 个），再考虑听力和答案
